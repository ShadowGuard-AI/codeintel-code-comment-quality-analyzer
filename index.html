codeintel-code-comment-quality-analyzer

The Scriptorium Desk. A command line analyzer that reads one Python file's comments, finds where they are missing, checks them against a supplied style guide, and flags the notes that may have gone stale beside the one example line it knows.

The repository main.py
InputOne Python file per run, through a positional filename
Missing commentsFound on the AST for functions, classes, and complex logic blocks
StyleChecked only when a style guide is supplied, honouring min_length and required_prefix on whole line comments
DependenciesNone. The standard library is all there is; requirements.txt is a comment saying so

Usage

python3 main.py FILE [--style-guide RULES.json] [--verbose]

The README parameter list names no positional argument at all, so the file never says what the analyzer is to be run on. The invocation above is the true one: one Python file per run. A file that cannot be read or parsed exits 1.

OptionWhat it does
FILEThe one Python file to evaluate.
--style-guideA JSON rules file. Style consistency runs only when one is supplied; the honoured keys are min_length and required_prefix, applied to whole line comments.
--verboseVerbose output.

The outdated check, stated plainly

  • The third check is a demonstration, and its own docstring says so. It searches for lines matching the single hardcoded example pattern result = val + 5.
  • Comments within three lines of a match that mention a word from that line are flagged, each flagged once.
  • It reads no code changes, no diffs, and no version control history, and it does not detect outdated or misleading comments in general.

Requirements

Python 3 with its standard library. Nothing to install.
